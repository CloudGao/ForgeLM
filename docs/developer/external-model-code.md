# 外部模型源码与平台代码版本

模型源码仓库负责开发历史，平台负责执行记录。两者无需共用 Git 仓库。

## 三类版本

| 对象 | 内容与用途 |
|---|---|
| Git commit / 外部开发目录 | 模型结构、训练实现、依赖声明与开发历史 |
| 平台 CodeVersion | 导入后冻结的代码快照、入口及来源；任务绑定此版本执行 |
| Checkpoint / ModelVersion | 训练状态、权重及登记的产物版本；关联生成它的任务 |

仅给权重登记模型版本，不能替代对训练程序的版本追踪。修改外部训练代码后，应再次通过平台导入，创建新的代码版本；不要覆盖已经冻结的快照。

## 现有接入方式

项目模型代码入口支持 Git、本地目录、归档和浏览器上传。Worker 必须能够访问来源；私有 Git 的访问能力由管理员在实际执行环境准备，凭据不要写进公开示例、代码快照或提交历史。

通用命令适配器通过 `executable/args/env/cwd` 启动引擎，并提供任务规格、运行目录、冻结输入、事件及制品协议。Checkpoint 的完整恢复、配置变更接续或仅权重恢复由引擎实现相应契约，平台负责冻结意图与追踪结果。

需要依赖隔离和可安装组件时，使用现有 `.flsuite` 机制：清单、节点 Schema、组件 entry point、依赖锁及哈希由平台验证，Worker 安装与执行。不要为了一个模型新增平台内置算法或另写任务编排服务。

## 从混合开发仓库分离

本地模型文件应保留，后续在独立模型仓库或本地目录维护。ForgeLM 仓库从已审查的平台快照开始维护独立历史；原混合开发仓库留作存档，不导入其提交历史。

本次公开源码保留对旧模型格式的可选兼容调用，但不包含其实现、训练循环、私有性能优化或模型依赖安装预设。模型需要自己提供代码版本或外部套件；平台基础安装和普通 Worker 部署不依赖模型仓库存在。
